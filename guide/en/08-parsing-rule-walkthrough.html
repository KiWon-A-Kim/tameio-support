8. Pasting Messages and Setting Up Message Recognition Rules — A Worked Example

Paste an approval or transaction message from your card issuer or bank and the app can fill in the amount, merchant, and date without typing them by hand. This chapter covers how to check which formats are already supported, and how to build your own message recognition rule for a format that is not.

Start with the privacy boundary

Tameio does not read your messages inbox. It only processes text that you copy from your notifications or messaging app and paste into the entry screen yourself, and that text is never sent off the device. The sample message you enter when creating a rule is stored locally as reference material for that rule; it is not sent to a server either.

Step 1 — Paste supported formats directly

Paste a card approval or account transaction message into the entry screen, and if it matches a registered rule the amount, merchant, date, and so on are filled in automatically. Nothing is saved automatically — check the filled-in values and tap save to record the transaction.

Step 2 — Create a new rule for formats that are not recognized

Messages from a new card issuer, or in unfamiliar wording, may not be filled in automatically. When that happens, open Message Recognition Rules from the Manage screen in the top menu, then choose Add Message Recognition Rule from the menu in the top right.

Example message (sensitive details removed; not real data):

[Web]
Example Card (1234) approved
$120.00 single payment
09/07 12:34
Merchant: Example Cafe
  1. Enter the message above as the sample on the add-rule screen.
  2. Following the guidance, mark the parts that correspond to the amount ($120.00), the date (09/07), and the merchant (Example Cafe).
  3. Set which transaction type this message is (expense, card payment, and so on), plus the default category and payment method (Example Card).

Advanced settings — when the automatic analysis picks the wrong place

At the bottom of the Automatic analysis step there is a collapsed Advanced settings section. You do not have to open it to create a rule — as the screen itself says, it is for when you want to "Use this only to fine-tune values suggested by the guided flow."

Which messages the rule applies to — recognition conditions

FieldWhat it means
Required words · One per lineEvery word you list here must appear in the message for the rule to match
Excluded words · One per lineIf even one of them appears, the rule is not applied
Word order · Example: deposit > transaction amountEach line is one group, and the words separated by > must appear in that order

All three fields take one entry per line. Things to know:

  • These are not regular expressions. The app only checks whether the text you typed appears in the message as-is.
  • Case and accents matter. CARD and card count as different words.
  • At least one of Required words or Word order must be filled in. Leave both empty and saving is blocked with "A criterion is needed to distinguish this message."
  • Word order allows at most 4 lines, with 2–8 words per line. Across all three fields you cannot exceed 16 distinct words.

Where to take the values from — exact extraction ranges

Use this when the automatic analysis picked the wrong amount or merchant. Drag to select the part you want in the sample message, choose the Field, then tap Use selected source range as a field. The seven fields you can choose from are Amount · Currency · Merchant or contact · Transaction Date · Financial institution hint · Account suffix hint · Installment Months.

  • If dragging is awkward, type the value exactly as it appears into Exact value in the sample and tap Add Directly Entered Value instead.
  • If the same value appears several times in the message, use Occurrence (1–8) to say which one you mean.
  • Choosing Amount also shows Decimal separator (default none) and Grouping separator (default comma). For messages like $120.00 set the decimal separator to a period.
  • For Currency, turning on Fixed currency code stops the app looking for a currency in the message and always records the code you set in Fixed currency. Use this for messages that carry no currency marker.
  • The fields you assign stack up below as entries like Amount · #1, and each row has a remove button.

Priority and test reference date

  • Priority (0–10,000) can only be adjusted when you are creating a rule. On an already saved rule the value is locked, and you change it with Edit order in the list instead (see "When several rules match at once" below).
  • Test reference date is not saved with the rule. It exists so you can test which date gets recorded when the message contains no date.

When editing or duplicating a saved rule

Open a rule by editing or duplicating it and a notice appears at the top — "The saved recognition and extraction pattern is preserved." — with the recognition condition fields locked. In that state the pattern saved earlier is what is used, not the sample you have entered now. To really change the conditions you must first tap Rebuild recognition pattern from current sample to unlock them.

Step 3 — Check the extraction result in the preview

Before saving the rule, use the Preview of what will be recorded card to check that the extracted amount, date, and merchant, and the category and payment method references you set, are correct. If you like, turn on the Keep original sample message switch to keep this sample message with the rule for later reference. Nothing is saved automatically here either — the rule is registered only when you save it yourself.

The last step — the rule name is the key

The rule name you set in the final Name and save step is not just the label shown in the list; the name itself is the key that identifies the rule. You cannot use the same name twice.

  • Saving with a name that already exists is rejected. Nothing is overwritten and nothing is merged.
  • The comparison is lenient. Leading and trailing spaces are stripped, and case and accents are ignored. So Card approval and card approval (with a trailing space), or Cafe and Café, count as the same name.
  • An archived rule still holds on to its name. Archiving a rule does not release the name, so to reuse it you have to rename the archived rule first.
  • Duplicating a rule pre-fills the name so that it does not collide when you save it as is.
  • Names can be up to 120 characters.

⚠️ The screen will not tell you that the name is the problem. After you tap save, all you get is the generic message "The rule couldn't be saved. Check the latest list and try again." The same wording appears for other causes too, so when you see it, check the list — including the "Archived" section — for the same name first.

Renaming a rule later keeps its identity, priority, and links intact. This name is also shown on the entry screen when a message is recognized, in the form Rule: <name> · <institution> · User rule, so it is worth choosing a name that will tell you later which rule matched.

Step 4 — Re-verify with a new message in the same format

After saving the rule, paste a new message from the same card issuer with a different amount and check that the rule applies correctly. Look at whether the rule recognizes amounts and dates consistently even when they arrive in slightly different shapes.

If something is recognized incorrectly, reopen the rule and correct the field assignments. If you want to replace it with a more accurate rule, move the old one to Archive in the list — archived rules move to the "Archived" section and are no longer applied to new messages, but they are not erased. Note, though, that archiving still keeps its name reserved, so you cannot give a new rule the same name (see "The rule name is the key" above).

Privacy notes

  • Never put sensitive values — full account or card numbers, real names, phone numbers — into a rule's sample, into a support request, or into any screenshot you share. Keep at most the last few digits of a card and the merchant name, and mask the rest.
  • When you write to support, include only the minimum needed to reproduce the problem: the shape of the message (where the line breaks are, which word sits where) and which value was recognized incorrectly, rather than real amounts and merchants.

When several rules match at once

Tap Edit order on the rule list screen and you can drag rules or move them with the arrows; that order is the priority. When several rules match the same message, they are applied in this order.

  1. Your own rules are always applied before the app's built-in rules.
  2. Among your own rules, the one higher up in Edit order is applied first.
